1. SOLUTION OVERVIEW
================================================================================

This demo showcases an enterprise-grade, ITSM-integrated Windows patching
pipeline for Ropes & Gray (law firm, 1,500+ attorneys, 16 global offices).

PRODUCTS INTEGRATED:
  - Jira Service Management (Cloud) — ITSM change tickets, workflow, automation
  - Red Hat Ansible Automation Platform 2.6 — Controller + EDA + Hub (all-in-one)
  - Microsoft Azure — Windows Server VMs, Update Manager, Snapshots
  - (Optional) Azure Update Manager — Scheduled patching assessment

FLOW SUMMARY:
  Engineer creates CHG ticket → Reviewer approves → Jira transitions to
  "Patch Windows" → Jira Automation fires webhook to EDA → EDA launches
  AAP Workflow → Pre-snapshot → Patch → Verify → Post Jira comment →
  Transition to QA Testing → QA approves or triggers rollback.

PAIN POINTS ADDRESSED:
  1. No formal change tickets for patching
  2. No pre-patch risk visibility
  3. Manual scheduling and execution
  4. Slow/risky rollback process
  5. Missing audit trails for compliance
  6. Fragmented multi-cloud management

  For the current demo, the URL is:
    https://aap.iisdemolab.click/eda-event-streams/api/eda/v1/external_event_stream/e04c1e6e-1c48-489f-961a-0ca15de3ad41/post/

  Create Basic Auth credential for the event stream:
    Username: jira-webhook
    Password: webhook123
    Base64:   amlyYS13ZWJob29rOndlYmhvb2sxMjM=

CRITICAL — JIRA URL COMPATIBILITY:
  Jira Cloud Automation's "Send web request" action converts underscores (_) to
  hyphens (-) in URLs. The native EDA event stream URL contains underscores
  (external_event_stream) which Jira mangles to (external-event-stream), returning 404.

  SOLUTION: Deploy an nginx reverse proxy on the AAP server (port 9443) with a valid
  Let's Encrypt SSL certificate. The proxy rewrites the hyphenated path back to
  underscores before forwarding to EDA on localhost:443.

  Nginx config location: /etc/nginx/conf.d/eda-rewrite.conf
  SSL cert: /etc/letsencrypt/live/aap.iisdemolab.click/fullchain.pem
  SSL key:  /etc/letsencrypt/live/aap.iisdemolab.click/privkey.pem

  The URL to use in Jira Automation rules:
    https://aap.iisdemolab.click:9443/eda-event-streams/api/eda/v1/external-event-stream/<UUID>/post/

  This proxies to the actual EDA URL:
    https://localhost/eda-event-streams/api/eda/v1/external_event_stream/<UUID>/post/

  To set up the nginx proxy:
    1. Install nginx: sudo dnf install -y nginx
    2. Install certbot: sudo pip3 install certbot
    3. Open port 80 temporarily in AWS SG for Let's Encrypt verification
    4. Get cert: sudo certbot certonly --standalone -d aap.iisdemolab.click --non-interactive --agree-tos --email your@email.com
    5. Create /etc/nginx/conf.d/eda-rewrite.conf with rewrite rules
    6. Open port 9443 in AWS SG to 0.0.0.0/0
    7. Start nginx: sudo systemctl enable --now nginx
    8. Close port 80 in AWS SG (no longer needed)

RULEBOOK DETAILS (jira_patch_rulebook.yml):
───────────────────────────────────────────
  2 rules:

  Rule 1: "Jira | Patch Windows - launch patch"
    Condition: event.payload is defined AND
               (event.payload.issue_status is not defined OR
                event.payload.issue_status != "Revert Patch")
    Action: run_job_template
      Name: "Hybrid Patch Workflow"
      Organization: "IIS Demo Lab"
      Extra vars from event:
        jira_ticket_id:  event.payload.issue_key
        jira_summary:    event.payload.issue_summary
        target_hosts:    "windows"
        dry_run:         "false"

  Rule 2: "Jira | Revert Patch - launch rollback"
    Condition: event.payload is defined AND
               event.payload.issue_status == "Revert Patch"
    Action: run_job_template
      Name: "Rollback Patch"
      Organization: "IIS Demo Lab"
      Extra vars from event:
        jira_ticket_id:  event.payload.issue_key
        jira_summary:    event.payload.issue_summary
        target_hosts:    "windows"

STEP 7.1: CREATE ACCOUNT & PROJECT
────────────────────────────────────
  1. Sign up at atlassian.com (free tier works)
  2. Create project:
     Template:    IT Service Management (service_desk project type)
     Name:        Change Management
     Key:         CHG
     Type:        Team-managed
     Issue Type:  "Change" (id: 10004), NOT "Task"
     Request Type: "Upgrade or change a server" (when creating tickets through the portal)

STEP 7.2: CREATE CUSTOM FIELDS (4)
────────────────────────────────────
  Project Settings → Issue Types → Change Request → Add fields:

  1. Patch Scope       | Short text  | e.g., "windows", "linux", "all"
  2. Maintenance Window| Short text  | e.g., "weekly-saturday-0200utc"
  3. Risk Level        | Dropdown    | Options: Low, Medium, High
  4. Rollback Required | Checkbox    | Boolean

  Associate all fields to the Change Request issue type screen.

STEP 7.3: CREATE WORKFLOW
──────────────────────────
  Project Settings → Board → Workflows → Add Workflow

  Name: "CHG: Azure Windows Infrastructure Management Workflow"

  Statuses (7):
    1. New CHG Request       (category: To Do)
    2. Under Review          (category: In Progress)
    3. Patch Windows (Automation) (category: In Progress)  — Automation trigger
    4. QA Testing            (category: In Progress)
    5. Accepted              (category: Done)
    6. Revert Patch          (category: In Progress)  — Rollback trigger
    7. Resolved              (category: Done)

  Transitions (6):
    New CHG Request   → Under Review        (Submit for Review)
    Under Review      → Patch Windows (Automation) (Approve & Start Patching)
    Patch Windows (Automation) → QA Testing  (Patching Complete)
    QA Testing        → Accepted            (QA Approved)
    QA Testing        → Revert Patch        (Request Rollback)
    Revert Patch      → Resolved            (Rollback Complete)

  Assign this workflow to the "Change Request" issue type in the CHG project.

STEP 7.4: CREATE API TOKEN
────────────────────────────
  Go to: https://id.atlassian.com/manage-profile/security/api-tokens
  Create token → Save the value (used in AAP Jira credential)

STEP 7.5: CREATE AUTOMATION RULES (2)
───────────────────────────────────────

  RULE 1: "Notify AAP on Implementing" (Patch Trigger)
    Project Settings → Automation → Create Rule

    WHEN:    Issue transitioned
               From status: "Under Review"
               To status:   "Patch Windows (Automation)"
    THEN:    Send web request
      URL:     https://aap.iisdemolab.click:9443/eda-event-streams/api/eda/v1/external-event-stream/e04c1e6e-1c48-489f-961a-0ca15de3ad41/post/
      NOTE:    URL uses hyphens (external-event-stream) because Jira converts underscores.
               The nginx proxy on port 9443 rewrites hyphens back to underscores for EDA.
      Method:  POST
      Headers:
        Content-Type:  application/json
        Authorization: Basic amlyYS13ZWJob29rOndlYmhvb2sxMjM=
      Body (Custom data):
        {
          "issue_key": "{{issue.key}}",
          "issue_summary": "{{issue.summary}}",
          "project_key": "{{issue.project.key}}",
          "issue_status": "{{issue.status.name}}",
          "issue_priority": "{{issue.priority.name}}",
          "reporter": "{{issue.reporter.displayName}}",
          "assignee": "{{issue.assignee.displayName}}",
          "timestamp": "{{now.iso8601}}"
        }

    Enable the rule.

  RULE 2: "Trigger AAP Rollback" (Rollback Trigger)
    WHEN:    Issue transitioned
               From status: "QA Testing"
               To status:   "Revert Patch"
    THEN:    Send web request
      URL:     https://aap.iisdemolab.click:9443/eda-event-streams/api/eda/v1/external-event-stream/e04c1e6e-1c48-489f-961a-0ca15de3ad41/post/
      NOTE:    Same port 9443 nginx proxy URL with hyphens (see Rule 1 note).
      Method:  POST
      Headers: (same as Rule 1)
      Body:    (same JSON payload — EDA differentiates by issue_status field)

    Enable the rule.

AZURE SNAPSHOT LOGIC (pre_change_snapshot role):
─────────────────────────────────────────────────
  1. Get Azure access token via REST:
     POST https://login.microsoftonline.com/<tenant_id>/oauth2/token
     Body: grant_type=client_credentials&client_id=<id>&client_secret=<secret>&resource=https://management.azure.com/

  2. Get VM details to find OS disk ID:
     GET https://management.azure.com/subscriptions/<sub>/resourceGroups/<rg>/providers/Microsoft.Compute/virtualMachines/<vm>?api-version=2023-09-01

  3. Create disk snapshot:
     PUT https://management.azure.com/subscriptions/<sub>/resourceGroups/<rg>/providers/Microsoft.Compute/snapshots/<name>?api-version=2023-10-02
     Body: location, tags (Purpose, Ticket, CreatedBy, SourceDisk), creationData (sourceResourceId = OS disk ID)

  4. If any step fails → warning only, does NOT block patching
     (block rescue pattern with debug warning)

JIRA COMMENT POSTING (post_change_verify role):
─────────────────────────────────────────────────
  1. Render comment from jira_comment.j2 template
  2. POST /rest/api/3/issue/<ticket>/comment
     Auth: Basic (base64 of jira_email:jira_token)
     Body: Atlassian Document Format (ADF) with code block
  3. GET /rest/api/3/issue/<ticket>/transitions (find target status ID)
  4. POST /rest/api/3/issue/<ticket>/transitions (transition to QA Testing)

ROLLBACK LOGIC (rollback_patch role):
──────────────────────────────────────
  1. Load KB list from C:\Windows\Temp\ansible_last_patch_kbs.json
  2. Uninstall each KB via: wusa.exe /uninstall /kb:<num> /quiet /norestart
  3. Reboot after all uninstalls
  4. Verify KBs removed via Get-HotFix
  5. Post rollback comment to Jira
  6. Transition ticket to Resolved (since ticket is already in 'Revert Patch' status)

14. KNOWN ISSUES & WORKAROUNDS
================================================================================

ISSUE 1: Jira webhook times out (30s) but job runs
  Cause:   EDA/AAP takes >30s to process; Jira considers it timed out
  Impact:  None — webhook was received, job runs fine
  Fix:     Ignore Jira timeout warning; verify in EDA Rule Audit

ISSUE 2: "Issue does not exist" (404) when posting Jira comment
  Cause:   jira_ticket_id not passed correctly from EDA event payload
  Fix:     Verify event payload field name matches rulebook extra_vars
           Check: event.payload.issue_key vs event.payload.key

ISSUE 3: Azure snapshot not created
  Cause:   Azure SP credentials not configured or insufficient permissions
  Fix:     Ensure Azure SP credential attached to job template
           Verify SP has Microsoft.Compute/snapshots/write permission
           Playbook uses block/rescue — failure is non-blocking (warning only)

ISSUE 4: CSP subscription cannot create resource groups
  Cause:   Restricted Azure subscription (CSP, MSDN, etc.)
  Fix:     Set use_existing_resource_group = true in terraform.tfvars
           Set existing_resource_group_name = "<your-rg>"
           Set deploy_azure = false if needed

ISSUE 5: WinRM connection refused
  Cause:   Windows firewall, NSG rules, or CSE script failed
  Fix:     1. Check Azure NSG allows 5986 from AAP IP
           2. RDP into VM, check WinRM: winrm enumerate winrm/config/listener
           3. Re-run CSE: az vm extension set ...

ISSUE 6: EDA rulebook activation not running
  Cause:   Decision environment not found, or controller credential invalid
  Fix:     1. Verify de-supported-rhel9 exists in Decision Environments
           2. Regenerate AAP API token and update EDA credential
           3. Check EDA controller logs: podman logs -f eda-server

ISSUE 7: Jira transition fails (no matching transition ID)
  Cause:   Workflow status names in Ansible don't match Jira workflow
  Fix:     Update group_vars/windows.yml status names to match exactly:
           jira_status_pending_qa: "QA Testing"
           (must match Jira workflow status name exactly, case-sensitive)

ISSUE 8: Jira Automation URL converts underscores to hyphens
  Cause:   Jira Cloud's "Send web request" action normalizes URLs, converting _ to -
  Impact:  EDA returns 404 because the path doesn't match
  Fix:     Deploy nginx reverse proxy on port 9443 with URL rewrite rule.
           Use hyphenated URL in Jira, nginx rewrites to underscore URL for EDA.
           See Section 6.2 for full setup instructions.

ISSUE 9: Jira webhook SSL handshake failure (certificate unknown)
  Cause:   AAP gateway uses a self-signed SSL certificate. Jira Cloud requires
           a valid, publicly-trusted certificate.
  Impact:  Jira sends webhook but TLS handshake fails, returns 500 to Jira
  Fix:     Install Let's Encrypt certificate on nginx proxy (port 9443).
           certbot certonly --standalone -d aap.iisdemolab.click
           Update nginx to use /etc/letsencrypt/live/aap.iisdemolab.click/fullchain.pem

ISSUE 10: Jira automation "SOME ERRORS" with HTTP 500 but job runs
  Cause:   EDA returns an empty 200 response body. Jira interprets empty body
           as error in some cases. The webhook IS delivered and processed.
  Impact:  Cosmetic — Jira audit shows "SOME ERRORS" but the job executes.
  Fix:     Ignore the Jira error. Verify job execution in AAP Jobs list and
           EDA Rule Audit. The 500 is a Jira display issue, not a real failure.

ISSUE 11: Ticket created as "Task" type instead of "Change" type
  Cause:   JSM projects use Request Types in the portal. If wrong request type
           is selected, ticket gets default Task workflow (Open/Done) instead of
           custom Change workflow with 7 statuses.
  Fix:     Use request type "Upgrade or change a server" (maps to Change issue type).
           Via API: use issuetype id "10004" (Change).

ISSUE 12: Rollback role path not found in AAP
  Cause:   rollback.yml referenced "rollback_patch" without relative path prefix.
           Other playbooks use "role: ../roles/..." but rollback.yml had bare name.
  Fix:     Changed to "role: ../roles/rollback_patch" to match other playbooks.

ISSUE 13: Rollback doesn't transition ticket after completion
  Cause:   Rollback role tried to transition to "Rollback Requested" status which
           doesn't exist. Ticket is already in "Revert Patch" — needs to go to "Resolved".
  Fix:     Updated rollback role to use jira_status_resolved ("Resolved") instead of
           jira_status_rollback_requested for the post-rollback transition.
